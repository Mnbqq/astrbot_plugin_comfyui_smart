ComfyUI 连接

AstrBot 所在机器能访问到的 ComfyUI 地址。

换大模型前先卸载上一套

切换底模家族（例如视频模型 ↔ SDXL）之前，先让 ComfyUI 释放显存与内存。16G 内存的机器上能避免切换时崩 os error 1455。默认开启。

多后端调度

有多个 ComfyUI 时按「谁闲给谁」自动分配，某台失败会临时熔断并跳过。单后端留空即可。

出图队列与并发

限制同时出图的数量，超出的先排队并告知位次，避免多人同时出图把显存打满。

ComfyUI 里的真实模型

直接读取 ComfyUI 的模型目录，不依赖手动填写。出图只会使用这里列出的模型。

切换到本页时自动读取。

提示词优化与选型

用 LLM 把中文描述改写成提示词，并从真实模型清单里挑选底模与 LoRA。

启用提示词优化与智能选型

关闭后直接用你的原话当提示词、用第一个可用底模，完全不需要 LLM。

视频提示词也交给 AI 改写

打开后 /视频 与 /图生视频 会先把描述改写成「视频提示词」：补全动作（缓缓回头、轻轻晃动）、镜头运动（固定 / 推近 / 平移）与光影氛围，并保持你原本的语言（中文就输出中文，Wan 原生懂中文）。与图片那套不同——图片是英文 tag，视频要自然语言的动作描述。视频用哪个模型由下面的「文生视频 / 图生视频默认模型」决定，AI 只改提示词。聊天里可用 --llm / --no-llm 临时覆盖。

反推专用模型

/反推 必须用支持看图的模型。若当前对话模型不支持看图，AstrBot 会把图片替换成「[Image]」，模型就会一本正经地编内容 —— 这就是「反推结果全错」的成因。

在 AstrBot「服务提供商」里添加一个支持看图的模型（如 qwen-vl-max、glm-4v、gpt-4o），把它的 ID 填在这里。

或：直连自定义接口

填了接口地址就不再走上面的提供商。

临时试别的模型可以不改配置：/反推 --provider <id>。用 /状态 可以看到当前用的是哪个看图模型、以及它是否支持看图。

默认出图参数

插件会按底模架构（SD1.5 / SDXL / Pony / Flux）自动适配分辨率、CFG 与采样器。

强制使用下面的参数

关闭时下面各项只在架构无法识别时兜底，避免把 SD1.5 的参数误用到 SDXL 或 Flux 上。

按架构自动补质量词

SD1.5 / Pony 系自动加质量词；SDXL / Flux 不加（加了可能反而变差）。

行内 --negative "..." 在任何档位都会生效。

图生图（以图为底重绘）

把图发给机器人并带上描述，就会以这张图为底重绘；也可以直接发图给 /图生图（别名 /改图）。

在 /画图 里带图时自动走图生图

关闭后带图也按文生图处理，仍可用 /图生图 显式调用。

重绘幅度：--denoise 0.3 只修细节、0.6（默认）改画风、0.8+ 接近重画。目标尺寸按原图比例计算，并对齐到 8 的倍数。

Hires Fix（放大重绘）

先出小图，再放大重绘一遍。改善手部、人脸与细节最有效的手段之一，代价是出图时间大致翻倍。

文生图自动启用

每次 /画图（文生图）都自动放大重绘一遍。

图生图也自动启用

需与上面的「文生图自动启用」同时打开才生效。

允许单次指令覆盖

打开后用户可以自行发 --hires 1.5 或 --hires 0；关掉则一律按这里的配置执行。

放大后尺寸 = 原尺寸 × 倍数，且会对齐到 8 的倍数。显存较小（如 8GB）时建议倍数不要超过 1.5。

视频（文生视频 / 图生视频）

用 /视频 按描述生成短视频；需要 ComfyUI 里已装好视频模型与节点（如 Wan 2.x）。

档位决定分辨率 / 帧数 / 步数上限：低配 480p · ≤97 帧 · ≤12 步；标配 720p · ≤121 帧 · ≤30 步；高配 720p · ≤161 帧 · ≤50 步。自动档按显存判定，内存不足 20G 再降一档。
低配 / 标配档下没指定模型时，会优先挑文件名带 turbo / lightning / distill / schnell 的加速版权重（实测 Turbo 4 步 74 秒 vs 原版 20 步 281 秒）；填了上面的模型名就以你填的为准。

直接把视频发到聊天

结果发送与图片保留
