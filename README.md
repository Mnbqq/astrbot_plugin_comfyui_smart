# AstrBot 的 ComfyUI 智能绘图插件

让 AstrBot 连接 ComfyUI，用一句自然语言出图：

> **/画图 一个白裙少女站在樱花树下**

插件读取你 ComfyUI 里**真实存在的模型**，识别底模架构（SD1.5 / SDXL / Pony / Flux），
自动匹配工作流模板、分辨率、CFG 与采样器，再用 LLM 把中文改写成提示词。

- **模板是数据**：`workflows/*.json` 是真正被加载的文件，可以直接换成你自己的 API 格式工作流
- **不靠猜**：模型、节点、参数都对着你 ComfyUI 的真实清单校验，缺什么、错在哪都直接说清楚
- 另有 Hires Fix、图生图、扩图（outpaint）、局部重绘（配置页涂抹遮罩）、看图反推提示词、
  无指令出图、统计与画廊、权限配额、出图并发与排队、多后端调度、实时进度与 `/取消`
- **界面格式也能直接用**：ComfyUI 里点「保存/导出」拿到的工作流（`nodes`/`links`/
  `widgets_values`）丢进 `workflows/` 会被自动转成 API 格式
- **多语言**：中文 / English 两套文案（`.astrbot-plugin/i18n/`，AstrBot 官方约定），
  配置里 `language` 可选 auto / zh-CN / en-US

---

## 快速开始

1. 把插件目录放进 AstrBot 的 `data/plugins/`，重启 AstrBot
2. 打开插件配置页，填写 ComfyUI 地址（如 `http://127.0.0.1:8188`）
3. 发 `/画图 你的画面描述`

**环境要求**：AstrBot >= 4.26.0、Python 3.10+、一个可访问的 ComfyUI。

下界不是拍脑袋写的，是 `tests/check_api_surface.py` 对着真实源码实测出来的：

| 用到的 API | 自哪个版本起提供 | 更早版本的行为 |
|---|---|---|
| `astrbot.api.web`（`json_response` / `file_response` / `request`） | v4.26.0 | **无回退**，这是硬下界 |
| `AstrBotConfig.save_config_async` | v4.27.0 | 自动回退到同步的 `save_config()` |

已在 **v4.26.0**、**v4.27.3**、**v4.28.1** 三个版本上跑通，均无问题。

> **不需要 LLM 也能用**：没配置对话模型时，插件直接拿你的原话当提示词、用第一个可用底模出图，
> 并在结果里注明。只有配了 LLM 才会做中文改写与模型选型。

| `/取消` | 取消自己正在排队或正在出图的任务（管理员：`/取消 全部`） | 所有人 |
| `/统计` | 出图统计与画廊 | 所有人 |
| `/刷新模型` | 重新读取模型清单 | **管理员** |
| `/帮助`（别名 `/comfy帮助`） | 显示帮助 | 所有人 |

### 行内参数

```
/画图 16:9 赛博朋克城市 --seed 42 --steps 30
/画图 一个白裙少女 --size 832x1216 --lora style/anime.safetensors:0.8
/画图 一只猫 --model juggernaut --hires 1.5
```

| 参数 | 别名 | 说明 |
|------|------|------|
| `--size` | `尺寸` `分辨率` | `1024x1536` 形式 |
| `--ratio` | `比例` | `1:1` `16:9` `9:16` `4:3` `3:4` `3:2` `2:3` `21:9` |
| `--width` / `--height` | `宽` `高` | 单个维度 |
| `--seed` | `种子` | 固定随机种子便于复现 |
| `--steps` / `--cfg` / `--sampler` / `--batch` | `步数` `采样器` `批次` | 采样参数 |
| `--lora` | | `文件名` 或 `文件名:强度`（0~2），也可只写关键词 |
| `--model` | `模型` | 底模关键词，支持省略目录前缀 |
| `--negative` | `负面` | 覆盖负面提示词 |
| `--hires` | `放大` | Hires Fix 放大倍数；`--hires 0` 表示本次关闭（可在配置页禁用单次覆盖） |
| `--hires-denoise` / `--hires-steps` | | 第二轮重绘幅度 / 步数（0 = 与首轮相同） |
| `--denoise` | `重绘` | 图生图的重绘幅度（0.05~1） |
| `--left` / `--right` / `--top` / `--bottom` | `左` `右` `上` `下` | 扩图时各方向扩展的像素数（自动对齐 8 的倍数）；**只写哪边就只扩哪边** |
| `--feather` | `羽化` | 扩图接缝的羽化像素（默认 40，越大越柔和） |
| `--seconds` | `时长` `秒` | 视频时长（默认取配置，受「时长上限」截断） |
| `--fps` | `帧率` | 视频帧率（默认 16） |
| `--length` | `帧数` | 直接给帧数，按视频模型要求的 `4n+1` 自动对齐 |
| `--provider` | | 仅 `/反推` 用：本次用哪个提供商看图 |
| `--画` | `--draw` | 仅 `/反推` 用：反推后直接按结果出图 |

尺寸会自动对齐到 8 的倍数，并限制在所选架构的像素预算内。

| 分组 | 说明 |
|------|------|
| `general` | 语言（auto / zh-CN / en-US） |
| `server` | ComfyUI 地址、出图等待上限、轮询间隔、排队补偿上限 |

| `draw_settings` | 兜底出图参数、强制架构、质量词开关、负面词策略、强制 VAE、默认负面词 |
| `hires` | Hires Fix：文生图开关、图生图开关、是否允许单次 `--hires`、倍数、重绘幅度与步数 |
| `vision_settings` | 反推专用模型：指定一个支持看图的提供商，或填自定义 OpenAI 兼容接口 |
| `i2i` | 图生图：是否跟随 `/画图`、默认重绘幅度、输入图最长边、上传子目录 |
| `output` | 群聊 @ 触发人、附带参数信息、实时进度与节流间隔、图片保留数量与天数 |
| `permission` | 白名单 / 黑名单 / 每日上限 / 冷却 / 管理员豁免 |
| `agent` | 无指令出图开关 |

> 管理员身份沿用 **AstrBot 自带的管理员设置**，插件不再单独维护一份名单。
> 打开「高级 → 启用无指令出图」后，对话模型会获得一个 `generate_image` 工具，
> 用户直接说「画一张雪夜里的白猫」即可触发（需要模型支持工具调用，默认关闭）。

**数据目录**：`data/plugin_data/astrbot_plugin_comfyui_smart/`
—— `catalog.json`（模型清单缓存）、`stats.json`（出图记录，供画廊回看与复现）、
`quota.json`（每日计数与冷却，**重启不清零**）、`workflows/`（你自己的模板）、`output/`（图片）。
所有写入都是「临时文件 + 原子替换」并带并发锁，多人同时出图不会互相覆盖。

## 工作流模板

模板是数据，不是代码。内置十个：

| 模板 | 适用 | 说明 |
|------|------|------|
| `sd_checkpoint` | SD1.5 / SDXL / Pony / Illustrious | 单文件底模通用图，参数随架构注入 |
| `img2img_checkpoint` | 同上 | 图生图：`LoadImage` + `ImageScale` + `VAEEncode` |
| `outpaint_checkpoint` | 同上 | 扩图：`ImagePadForOutpaint` 画布外扩 + `SetLatentNoiseMask` 只重画新区域 |
| `inpaint_checkpoint` | 同上 | 局部重绘：`LoadImageMask` 读遮罩 + `GrowMask` 外扩 + `SetLatentNoiseMask` 只重画遮罩内 |
| `wan_t2v` | Wan 2.x 视频模型 | 文生视频：`UNETLoader` + `CLIPLoader(type=wan)` + `EmptyHunyuanLatentVideo` + `ModelSamplingSD3` + `SaveWEBM` |
| `wan_i2v` | Wan 2.x I2V 权重 | 图生视频（首尾帧）：`WanFirstLastFrameToVideo`（`start_image` / `end_image` 都是可选输入） |
| `wan22_t2v_gguf` | Wan 2.2 TI2V-5B **GGUF** | 文生视频（省显存）：`UnetLoaderGGUF` + `CLIPLoaderGGUF(type=wan)` + `Wan22ImageToVideoLatent` |
| `wan22_i2v_gguf` | 同上 | 图生视频（首帧驱动）：`Wan22ImageToVideoLatent.start_image` 接一张 `LoadImage` |
| `flux_checkpoint` | 一体化 Flux 单文件底模 | 模型/文本编码器/VAE 打包在一起的版本 |
| `flux_unet` | 分离权重的 Flux | `diffusion_models` 的 UNET + `text_encoders` 的 CLIP + 独立 VAE |

### 架构自适应

| 架构 | 默认分辨率 | 步数 | CFG | 采样器 / 调度器 | 负面词 |
|------|-----------|------|-----|----------------|--------|
| SD1.5 | 512x768 | 25 | 7.0 | dpmpp_2m / karras | 生效 |
| SDXL | 1024x1024 | 28 | 6.0 | dpmpp_2m / karras | 生效 |
| Pony / Illustrious | 1024x1024 | 28 | 7.0 | dpmpp_2m / karras | 生效（自动加 `score_*` 排除词） |
| Flux | 1024x1024 | 20 | 1.0 | euler / simple | **不生效**（改用 guidance 3.5） |
| 未识别 | 512x768 | 25 | 7.0 | dpmpp_2m / karras | 生效（按 SD1.5 处理） |

识别规则：名字含 `xl` / `juggernaut` / `realvis` → SDXL；含 `pony` / `illustrious` / `noobai` → Pony；
含 `flux` → Flux；含 `sd3` → SD3；**其余兜底 SD1.5**（社区惯例是 SDXL 系模型名里都带 `xl`）。
识别不准时用配置页的「强制指定架构」覆盖。

### 放自己的模板

把工作流 JSON 放进数据目录下的 `workflows/`（配置页「状态」页会显示完整路径），刷新插件即可。
**API 格式与界面格式都支持**（界面格式会被自动转换，见下一节）。三种写法：

1. **裸工作流**（推荐）：直接是 ComfyUI 导出的 API 格式，顶层是 `{"节点id": {...}}`。
   注入点由**图结构**推导，不依赖节点 id 或标题 —— 见下一节。
   界面里「保存」出来的 `{"nodes": [...], "links": [...]}` 也放在这里，会自动转换。
2. **带元信息**：外面套一层
   `{"name": ..., "arch": "flux", "loader": "unet", "purpose": "outpaint", "params": {...}, "graph": {...}}`。
   `arch` 可为 `sd15` / `sdxl` / `pony` / `flux` / `sd3` / `generic`；`loader` 为 `checkpoint` 或 `unet`；
   `purpose` 为 `t2i` / `i2i` / `outpaint` / `inpaint`（决定这个模板什么时候会被选中）。
   `params` 用来声明「这个工作流有哪些可注入参数」：`{"left": "5", "feathering": "5"}` 表示
   参数 `left` / `feathering` 写进 5 号节点。插件只会写模板声明过的键，写错节点或输入键在**加载时**就报错。

   > 为什么需要 `params`：扩图这类工作流的参数（左右上下扩展量、羽化）只有模板知道该写哪个节点，
   > 插件不会凭空往节点上塞字段（塞了会被 ComfyUI 以 `invalid_input_type` 拒绝）。

## 多语言（中文 / English）

配置里「通用 → 语言」可选 `auto` / `zh-CN` / `en-US`：

- `auto`（默认）：跟随 AstrBot 的界面语言；拿不到就用中文；
- 切换后**聊天文案、LLM 提示词、插件页导航与标签页标题**都会跟着换。

文案文件按 **AstrBot 官方约定**放在插件根目录：

```
.astrbot-plugin/i18n/
├── zh-CN.json    ← 中文（默认，始终保证齐全）
└── en-US.json    ← English
```

文件就是「键 → 文案」的 JSON 对象，文件名即语言代码（AstrBot 自己也会加载它们，
放进插件元数据的 `i18n` 字段）。想加一门语言，复制一份改名再翻译即可 —— 不用改代码。

键是分层的：`cmd.*`（指令与用法）、`queue.*`（排队与进度）、`result.*`（出图结果）、
`error.*`（面向用户的报错）、`perm.*`（权限与配额）、`llm.*`（发给模型的提示词）、
`ui.*`（插件页元素）。文案里可以用 `{name}` 占位，`t("perm.cooldown", seconds=5)` 会填充；
**参数缺失或键不存在都不会抛错**（最坏情况是显示键名，而不是把指令搞崩）。

> 覆盖范围说明（实话）：聊天侧文案、权限提示、LLM 提示词、插件页的**导航 / 标签页标题 /
> 主要按钮**已经双语；插件页卡片里的**细粒度字段说明**、以及 ComfyUI 底层报错原文
> （例如 `value_not_in_list` 的细节）仍是中文。测试里有一条守卫：**源码里引用到的每一个键，
> 两种语言都必须有**，所以不会出现「加了新文案只写中文」的漂移。

## 界面格式自动转换

插件认的是 **API 格式**（开发者模式里 Export (API) 拿到的那种），但你在 ComfyUI 界面里
点「保存 / 导出」拿到的是**界面格式**：

```json
{ "nodes": [{"id": 3, "type": "KSampler", "widgets_values": [12345, "randomize", 28, 6.0, ...],
             "inputs": [...], "outputs": [...]}],
  "links": [[1, 4, 0, 3, 0, "MODEL"], ...] }
```

这种文件**直接丢进 `workflows/` 就能用**，插件会自动转成 API 格式再走完整的校验与注入。
转换时处理的是界面里真实存在、但容易踩坑的东西：

| 界面里的东西 | 转换时的处理 |
|---|---|
| `links` 表 + 各节点的 `inputs[].link` | 还原成 `[节点id, 槽位]`；顶层 `links` 缺失时用 `outputs[].links` 反推 |
| `control_after_generate`（种子后面的「生成后控制」） | **丢掉**。它只是界面控件，不是节点输入 —— 用 `/object_info` 顺序硬套会把 `steps`/`cfg` 整体错位一格 |
| 图片加载节点的 `upload` 控件 | 丢掉（同理） |
| `Reroute` 理线节点 | 穿过：把上游直接接到下游，不留在图里 |
| 静音（`mode=2`）的节点 | 跳过（界面里它本来就不执行） |
| 旁路（`mode=4`）的节点 | 按槽位穿过 |
| `PrimitiveNode` 之类的原语节点 | 不落地成节点，值直接写进下游输入 |
| 节点标题 | 带进 `_meta.title`，「按标题找注入点」的兜底继续有效 |

控件名怎么来的（按优先级）：节点自带的 `inputs[].widget.name`（新版导出）→ `/object_info`
的输入顺序 → 内置的常见节点表。三条都不成立、或控件数量对不上时**明确报错**并说清是哪个节点、
期望几个值、实际给了几个，而不是转出一张会画错的图。

> 老版本 ComfyUI 的导出里没有 `widget` 名字信息，这时转换依赖 `/object_info`（插件会缓存上一次
> 拉到的结果）或内置表；两者都覆盖不到的自定义节点，请用「开发者模式 → Export (API)」导出。

## 注入点是怎么找到的

模板可以是任意来源的工作流，节点 id 千变万化（`3`、`KSampler_1`、`节点 27` 都常见），
所以插件**读图结构，不读节点编号**。三步依次尝试，前一步失败才走下一步：

**1）图语义推导（主路径）**
从采样器的 `positive` / `negative` 连线**向上游回溯**，找到第一个真正带文本输入的节点。
中间节点会被穿过（Flux 的 `FluxGuidance` 就夹在提示词与采样器之间）。
同一套语义推导还负责定位：尺寸节点（`EmptyLatentImage` / `EmptySD3LatentImage` / `ImageScale`）、
模型加载器（`CheckpointLoaderSimple` / `UNETLoader`）、`VAELoader`、`LoraLoader`、`SaveImage`。

**2）节点标题兜底**
用标题（ComfyUI 导出的 `_meta.title`，或顶层 `title`）匹配「正面 / 负面 / 尺寸 / 采样 / 保存」等关键词。
输入键不叫 `text` 的自定义提示词节点（如 `wildcard_text`）靠这一步定位。

**3）`bindings` 显式点名（最可靠）**
直接写死角色与位置，可写节点 id 或标题：

```json
{
  "name": "my_workflow",
  "bindings": {
    "positive": { "title": "正面提示词" },
    "negative": { "node": "13", "input": "wildcard_text" },
    "sampler":  { "node": "5" },
    "model_loader": { "node": "1", "input": "ckpt_name" },
    "save": { "node": "7" }
  },
  "graph": {}
}
```

支持的绑定角色：`positive` `negative` `sampler` `latent` `model_loader`
`vae_loader` `lora_loader` `save` `guidance`。`input` 可省略，插件按节点结构推断。
**绑定写错在加载时就报错**（节点不存在、标题匹配不到、输入键不存在、角色名不认识），
不会拖到出图才失败 —— 错误会显示在配置页「状态」页与 `/模板列表`。

两条硬规则：

- 提示词与尺寸只会写进节点上**真实存在**的输入键，绝不凭空塞一个 `text` 或 `width` 字段
  —— 凭空塞会被 ComfyUI 以 `invalid_input_type` 拒绝。
- 尺寸写在**真正决定尺寸的那个节点**上：文生图写空潜空间节点，图生图则写在 `ImageScale` 上
  （图生图的潜空间来自 `VAEEncode`，它根本没有 `width` / `height`）。
  Hires Fix 的放大目标尺寸也按同一规则推导：读不到就改用按比例放大，
  **绝不瞎猜一个 512x512 把画面压变形**。

## 校验与能力探测

插件的原则是：**能在本地确定的，就不要丢给 ComfyUI 去拒绝**。分四层。

### 1）载入模板时：图结构校验

模板一载入就被严格校验 —— 每个节点的 `class_type` 与 `inputs` 必须存在，
每条连线（`[节点id, 槽位]`）的目标节点必须真的在图中，`bindings` 的每个角色都必须解析成功。
任何一条不过，该模板**不会被加载**，并在配置页「状态」页与 `/模板列表` 里列出原因。

同时会**剔除不可达节点**：从 `SaveImage` 反向做可达性分析，把游离在外的孤儿节点摘掉。
这一步不是洁癖 —— ComfyUI 会校验整张图里每个节点的 `class_type`，
一个残留的、缺自定义节点的孤儿节点会导致整个任务被拒绝。

### 2）成图前：节点能力探测

用 `GET /object_info` 拿到你 ComfyUI **已安装**的节点类名清单（缓存 5 分钟，不拖慢每次出图），
然后按顺序挑模板：按用途筛（文生图 / 图生图）→ 按加载方式筛（`checkpoint` / `unet`）→
排除缺节点的模板 → 按架构精确匹配。

若选中的模板仍缺节点，**根本不会提交**，直接告诉你缺哪个：

> 模板 sd_checkpoint 需要以下节点，但你的 ComfyUI 没有安装：SaveImage。

两项连带检查：

- **架构相容性**：Flux 模板不会被套到 SD 模型上，反之亦然。SD1.5 模型被误放进
  `diffusion_models` 目录时，会给出可操作的中文提示，而不是提交一张必然失败的坏图。
- **模型、VAE、LoRA 的取值**都对照真实清单校验（含子目录写法 `SDXL/xxx.safetensors`），
  报错时直接把**可用项**列出来。模型清单只统计真正的模型目录，
  `custom_nodes`、`configs`、`embeddings` 这类不算模型。

### 3）提交前：本地预检（只诊断，不拦截）

用你 ComfyUI 自己的 `/object_info` 输入约束，把要注入的参数先本地校验一遍
（下拉取值是否在可选项里、数值是否越界），把最常见的拒绝原因提前说清：

```
提交前的本地校验未通过（按你 ComfyUI 的输入约束检查）：
　· 节点 5（KSampler）的 sampler_name 取值 'dpmpp_2m' 不存在（可用项：euler、dpmpp_2m_sde）
　· 节点 5（KSampler）的 steps=0 小于最小值 1
```

**为什么只诊断、不拦截**：有些节点用 `VALIDATE_INPUTS` 自己校验输入
（典型是 `LoadImage`，它接受 `子目录/文件名` 这种不在下拉列表里的写法），
拿下拉清单硬卡会误杀完全合法的请求。所以**服务端始终是最终裁判**，
预检结论只在服务端拒绝时作为线索一并给出。

### 4）失败时：让下一次失败自证

少数 ComfyUI 构建（含各类整合包）拒绝出图时只回一句 `prompt_outputs_failed_validation`，
`details` 与 `node_errors` 都是空的，报错本身没有任何信息。遇到这种情况插件会：

- 把**实际提交的工作流**完整落盘到数据目录的 `last_failed_prompt.json`
  （含时间、插件版本、ComfyUI 地址、错误原文与 `graph`），可直接发出来定位；
- 记录正向提示词长度、所用模板、底模与 LoRA；
- 提示你去看 ComfyUI 控制台里 `Failed to validate prompt for output` 附近的日志。

正常失败则会把节点级原因翻译成中文，例如：

```
提交失败：Prompt outputs failed validation
　· Return type mismatch between linked nodes: model, MODEL != CLIP
　· 节点 8（LoraLoader）：lora_name 取值 'ghost.safetensors' 不存在（可用项：a.safetensors、b.safetensors）
```

## 多后端调度

有两台机器（或一个 ComfyUI 开了多个实例）时，插件可以「谁闲给谁」：

| 配置 | 默认 | 作用 |
|---|---|---|
| 其他 ComfyUI 地址 | 空 | 每行一个，支持「地址\|名称」，例如 `http://192.168.1.20:8188\|二号线`；**主地址仍用上面的「服务地址」** |
| 调度策略 | `least_queue` | `least_queue` 谁闲给谁 / `round_robin` 轮流派 / `primary` 只用主后端 |
| 失败熔断时长 | `60` 秒 | 某台提交失败或探测不通后，这段时间内不再派任务给它；`0` = 不熔断 |

决策依据是每台的**队列负载**：正在执行的算 2 分、排队的算 1 分（正在跑的那个还占着显存），
挑分数最低的那台。选中的后端名会出现在出图消息里（多后端时），`/状态` 会逐台列出：

```
　后端（2 个，按负载分配）：
　　- 主（主） http://192.168.1.10:8188｜✅ 队列 6
　　- 二号线 http://192.168.1.20:8188｜✅ 队列 0
```

几条实话：

- **单后端时零开销**：没填「其他地址」就完全不探测，行为与没有这个功能时一模一样。
- **只有「连不上 / 超时 / 404 / 5xx」才熔断**：工作流参数写错是用户侧问题，不该把一台好机器拉黑。
  探测走的是 `/queue` 的严格模式（读不到就报错），否则一台挂掉的机器会以「队列 0」的假象抢到任务。
- **模型清单只从主后端发现**：多机共享同一份模型目录是常见前提。某台缺模型时，
  提交会得到 ComfyUI 的明确报错（不会静默换一台重试，否则你永远不知道是哪台缺）。
- **全部熔断时会回退到主后端**：宁可让主后端报出真实错误，也不让插件自己造一个「没有可用后端」的假错误。

## 并发与排队

多个人同时发 `/画图` 时，插件不会把任务一股脑全丢给 ComfyUI，而是先在自己的队列里排：

| 配置 | 默认 | 作用 |
|------|------|------|
| 同时出图上限 | `1` | 同一时间最多有几个任务在 ComfyUI 里跑，超出的在插件侧排队 |
| 单人同时出图上限 | `1` | 同一个人最多同时几个任务在跑，0 = 不限制 |
| 排队等待上限 | `300` 秒 | 在插件侧最多排多久，超时明确告知并取消，0 = 不限制 |

排队的人会收到一条提示，说清自己在等谁：

```
⏳ 前面还有 2 个任务，排队中（同时出图上限 1）…
⏳ 你已有一张在出，本次排队等待（同时出图上限 1）…
```

**两层队列，别混淆**（提示语不同，含义不同）：

- **插件侧排队**（上面那两句）：还没拿到名额，任务**没有**提交给 ComfyUI；
- **ComfyUI 队列**（`⏳ 已提交，队列第 N 位`）：已经提交过去了，等 ComfyUI 自己轮到它。

等前面的人做完，插件才放行下一个。出图消息里的「⏳ 排队等待 Ns」与总耗时是分开记的，
所以「这次为什么慢」能一眼分清是排队还是采样慢。

关于口径，说清楚几点：

- 「同时进行」= 从提交给 ComfyUI，到取回图片的整个过程；Hires Fix、图生图同样算一次，不会因为多跑一轮就额外占名额。
- ComfyUI 单卡本身是**逐个执行**提示词的，所以默认 `1` 主要买到的是「队列不被灌满、顺序公平、等待可预期」，而不是性能提升。**多卡、或你的 ComfyUI 开了并行执行时**，把上限调大才真的会同时跑。
- 单人上限挡住队首时会**跳过**它继续看后面的人：否则一个人连发十次 `/画图` 就能把队伍堵死。所以极端情况下，你看到的位次可能比实际轮到的顺序更靠前一点。
- 插件被禁用/重载时，排队中的人会被立即唤醒并收到「插件正在重载」的提示，不会一直挂到超时。

`/状态` 里能看到实时情况：

```
　并发：上限 1｜进行中 1｜排队 2｜单人上限 1｜排队等待上限 300 秒
```

## 实时进度与取消

出图不再是「发完等着」。插件连上 ComfyUI 的 WebSocket（`/ws`），把采样进度推回聊天：

```
🎨 采样中 3/28（10%）　用 /取消 可以中止这次出图
⏳ 已提交，队列第 2 位（前方 1 个任务）      ← 位置变化时才再提一次
```

- **进度按「最小间隔」节流**（默认 5 秒，配置页可调，0 = 不节流），同一百分比不重复发；
  `100%` 一定发一条，收个尾。关掉「出图过程中发送实时进度」就一条都不发。
- **连不上 WebSocket 不影响出图**：老版本 ComfyUI、反向代理没转发 WebSocket、防火墙拦截，
  都会安静退回轮询（日志里是 debug 级），出图流程完全不变 —— 进度只是锦上添花。
- 进度事件按 `prompt_id` 过滤，**别人的任务进度不会发到你这里**。

`/取消` 能停掉自己这次出图，两种情况都覆盖：

| 你的任务在哪 | 插件做的事 |
|---|---|
| 还在**插件侧排队**（没拿到并发名额） | 直接把排队中的请求摘掉，不必等到排队超时 |
| 已经提交但**还在 ComfyUI 队列里** | `POST /queue {"delete": [...]}` 把它从队列移除 |
| **正在执行** | `POST /interrupt` 打断当前采样 |

```
🛑 已取消
　· 已中断正在执行的任务
```

只能取消自己的任务；管理员可用 `/取消 全部` 清掉所有人的在途任务（插件卸载/重载时也会这样做）。

## 扩图（outpaint）

把画面往外扩，补全被裁掉的构图。发图 + `/扩图` 即可：

```
/扩图 把画面往两边扩成宽幅              ← 四周各扩原图的 25%
/扩图 --left 256 --right 256           ← 只往左右扩（上下保持 0）
/扩图 往下补出脚和地面 --bottom 384 --top 0
/扩图 换成雪景 --left 384 --right 384 --feather 64
```

| 行为 | 说明 |
|---|---|
| 用什么节点 | ComfyUI **自带**的 `ImagePadForOutpaint`（画布外扩）+ `SetLatentNoiseMask`（只重画新区域），**不需要额外模型或自定义节点** |
| 原图会不会被改 | 不会。遮罩把原图区域标成「不要动」，采样只作用在新扩出来的区域（所以 `denoise` 固定 1.0） |
| 默认扩多少 | 每边扩原图对应边长的 25%（至少 64px），自动对齐 8 的倍数 |
| 只扩某几边 | 写了 `--left/--right/--top/--bottom` 里任意一个，就**只用你写的这些边**，其余为 0 |
| 接缝有痕迹 | 调大 `--feather`（默认 40，最大 256）：羽化就是接缝处的过渡带宽度 |
| 会不会爆显存 | 会兜底：扩展后的总像素超过 2048×2048 预算时，扩展量按比例自动压回，并在日志里写明 |
| 输出尺寸 | 原图 + 四周扩展量；出图消息里会写清楚「640x960 → 1152x960」 |

> 想扩到指定画幅（比如 16:9）？先用 `--ratio` 看 `/画图` 的预设尺寸，再按差值填 `--left/--right/--top/--bottom`。
> 扩图模板用的是核心节点，但**很老的 ComfyUI 版本可能没有** `ImagePadForOutpaint`；
> 缺节点时插件会在提交前直接告诉你缺哪个，而不是提交一张必然失败的图。

## 文生视频（/视频）

```
/视频 一只猫在草地上奔跑 --seconds 5 --fps 16
/视频 赛博朋克城市延时摄影 --ratio 16:9 --steps 30 --seed 42
/视频 雪夜里的白狐 --length 49        ← 直接给帧数（会按 4n+1 对齐）
```

| 参数 | 说明 |
|---|---|
| `--seconds` | 时长；默认取配置里的「默认时长」，超过「时长上限」会被**截断**（日志里写明），帧数向下对齐以保证最终时长不超上限 |
| `--fps` | 帧率；默认 16。帧数 = 时长 × 帧率，并按视频模型要求的 **`4n+1`** 对齐（宁可多一帧，不少给） |
| `--length` | 直接指定帧数（优先于 `--seconds`），同样对齐 |
| `--size` / `--ratio` / `--width` / `--height` | 分辨率；Wan 档案默认 **832x480**、`uni_pc` + `simple`、CFG 6 |
| 其余 | `--steps` `--seed` `--model` `--negative` 与 `/画图` 一致 |

**前置条件（很重要）**：能不能真出片**取决于你 ComfyUI 里装了什么**，插件只负责把工作流配对好：

- 内置模板 `wan_t2v` 走 **ComfyUI 原生 Wan 2.x**，需要：
  - `diffusion_models` 里有 Wan 权重（如 `wan2.1_t2v_1.3B_fp16.safetensors`）；
  - `text_encoders` 里有 `umt5_xxl_*.safetensors`；
  - `vae` 里有 `wan_2.1_vae.safetensors`；
  - 节点：`UNETLoader` / `CLIPLoader` / `VAELoader` / `EmptyHunyuanLatentVideo` /
    `ModelSamplingSD3` / `SaveWEBM`（都是 ComfyUI 自带）。
- **缺模型或缺节点会在提交前直接说清楚**（缺哪个节点、可用项有哪些），不会静默失败。
- 想用别的视频模型（HunyuanVideo / LTX-Video / Mochi…）：把对应的 API 格式工作流
  丢进模板目录并声明 `"purpose": "t2v"` 即可，参数用 `params` 声明
  （`{"length": "潜空间节点id", "fps": "保存节点id"}`）。

**显存与耗时**：视频比出图慢一个数量级，也更容易爆显存。建议先 4 秒、832x480、30 步试水；
8.5 GB 显存跑 14B 级模型大概率放不下，1.3B / 5B 或低分辨率短时长更现实。
配置里的「时长上限」就是给这件事兜底的。

产物是 webm/mp4：插件会**直接把视频发到聊天**（AstrBot 的 `Video` 组件）；
平台发不了视频时，把「直接把视频发到聊天」关掉，改为在聊天里给出本地保存路径。
画廊里的视频条目用 `<video>` 渲染，点开可播放。

### 显存不够？用 GGUF 量化（Wan 2.2 TI2V-5B）

8 GB 显存 / 16 GB 内存的机器跑 fp16 视频权重很吃力。插件内置两个 **GGUF** 模板，
配合 ComfyUI-GGUF 自定义节点（`UnetLoaderGGUF` / `CLIPLoaderGGUF`）就能跑：

| 文件 | 大小 | 放到 |
|---|---|---|
| `Wan2.2-TI2V-5B-Q4_K_M.gguf` | 3.2 GB | `models/unet_gguf/` |
| `umt5-xxl-encoder-Q4_K_M.gguf` | 3.4 GB | `models/clip_gguf/` |
| `Wan2.2_VAE.safetensors` | 1.3 GB | `models/vae/` |

- 这套是 **TI2V**（文生 + 图生视频同一个模型）：`/视频` 走 `wan22_t2v_gguf`，
  `/图生视频` 走 `wan22_i2v_gguf`（把首帧接进 `Wan22ImageToVideoLatent.start_image`）。
- 采样参数按官方示例：**832x480 / 20~30 步 / CFG 5.0 / uni_pc + simple**（Wan 2.2 的 CFG 与 2.1 不同，
  所以插件给 TI2V 单独建了架构档案）；`ModelSamplingSD3` shift=8。
- **帧率/帧数很关键**：Wan 按 24fps、81~121 帧训练。插件从 v0.15.4 起没写参数时就用
  **24fps / 81 帧**（官方最长 121 帧 / 5 秒）。用 16fps 甚至 8fps 出片并按原速播放，
  看起来会像「静止糊图」——这是模型原生节奏决定的，不是插件没画。
- **输出是 mp4（h264）**：从 v0.15.5 起模板用 `CreateVideo` + `SaveVideo` 输出 mp4。
  之前的 WebM/VP9 在很多聊天端会显示成「0 秒」甚至播不出来。
- **装载方式不会串**：GGUF 模型只会挑 GGUF 模板，safetensors 模型只挑 safetensors 模板
  （`UnetLoaderGGUF` 和 `UNETLoader` 是两个不同的节点，混用必然报错）。
- 视频任务在没指定 `--model` 时会**优先从 `diffusion_models` / `unet_gguf` 里挑**，
  不会拿 `checkpoints` 里的图片底模去硬套；实在没有视频权重会明确告诉你该放哪里。

> **GGUF 文件该放哪个目录？** 不同版本/安装的 ComfyUI-GGUF 注册的目录不一样。
> 在浏览器打开 `http://<你的ComfyUI地址>/experiment/models`，就能看到每个目录名的
> **真实路径**。实测过一台机器：
> `unet_gguf` → `models\unet` + `models\diffusion_models`，
> `clip_gguf` → `models\text_encoders` + `models\clip`
> —— 也就是说 GGUF 权重应该扔进 `diffusion_models` / `text_encoders`，
> 而不是那个同名的 `unet_gguf` 空目录。插件从 v0.15.3 起**只看 `.gguf` 扩展名**挑模板，
> 所以无论放哪个被注册的目录里都能认出来。
> 放好后可发 `/刷新模型`，或直接问接口确认：`/models/unet_gguf` 与
> `/object_info/UnetLoaderGGUF` 里应该能看到你的文件名。

### 中文提示词能不能用？

实测（同一句中英文语料）：

- **视频（Wan，umt5 文本编码器）：能。** 用你这句
  「可爱的萝莉猫娘穿着白色丝袜，身着白黑短裙与红色披风，双手抱物立于室内房间中」
  文生视频，猫耳、白裙、红披风、室内场景都还原了。
- **图片（SD1.5 底模）：不能。** SD1.5 的 CLIP 只认英文，同样一句中文交给
  `3Guofeng3_v34`（这台机器上按字母序选中的第一个底模）只会出一张「白裙少女在窗边」，
  猫耳与红披风全丢了。两个办法：① 配置里打开 **LLM 提示词优化**（它会把中文改写成英文 tag）；
  ② 直接写英文提示词。想固定用某个底模，就在 `draw_settings.default_checkpoint` 里指定。

### 想让它「动起来」：提示词写动作

实测（Wan 2.2 TI2V-5B GGUF、同一张首帧、81 帧 @24fps）：

| 提示词 | 步数 | 相邻帧平均像素差 |
|---|---|---|
| 她慢慢转头 | 20 | 2.5（几乎不动） |
| 她转头看向镜头、长发随风飘动、镜头缓缓推近 | 30 | 7.9（明显在动） |
| **（你的提示词）猫娘…立于室内房间中** | 30 | **1.3（完全静止）** |
| **（你的提示词）+ 缓慢回头** | 30 | **8.5（一路把头转过去）** |

结论：图生视频**只描述画面会几乎不动**，要写清「谁做什么动作、镜头怎么动」；
步数 20 → 30 也有明显差别。

## 图生视频（首尾帧）

让一张图动起来；给两张图就是「首帧 → 尾帧」的过渡：

```
/图生视频 让她的头发和裙摆随风飘动 --seconds 3
/图生视频 镜头缓慢推近 --ratio 16:9 --fps 16
/图生视频 从白天过渡到夜晚        ← 发两张图（或引用一张再发一张）：第一张首帧、第二张尾帧
```

| 细节 | 说明 |
|---|---|
| 用哪个节点 | ComfyUI 自带的 `WanFirstLastFrameToVideo`（配合 `UNETLoader` / `CLIPLoader(type=wan)` / `VAELoader` / `ModelSamplingSD3` / `SaveWEBM`） |
| 为什么要两份图 | 该节点的 `start_image` 与 `end_image` 都是**可选**输入：只给首帧就是「从这张图开始动」，给两张就是「从首帧过渡到尾帧」 |
| 只给一张时 | 插件会把 `end_image` 从图里**摘掉**，并剪掉没用到的第二张 `LoadImage` —— 否则那条死链会指向占位文件名，ComfyUI 会直接拒掉整张图 |
| 尺寸 | 按输入图比例贴合，宽高对齐到 **16 的倍数**（视频模型的硬要求），并压到 832×480 的像素预算内 |
| 时长/帧率 | 与 `/视频` 完全一致（`--seconds` / `--fps` / `--length`，帧数按 `4n+1` 对齐、受「时长上限」截断） |
| 前置条件 | 需要 `diffusion_models` 里的 **Wan I2V 权重**（如 `wan2.1_i2v_480p_14B_fp8_e4m3fn.safetensors`）+ `text_encoders` 的 `umt5_xxl` + `vae` 的 `wan_2.1_vae`；缺什么会在提交前说清楚 |

> 想用别的模型（HunyuanVideo I2V、LTX-Video 等）？把对应的 API 格式工作流放进模板目录，
> 声明 `"purpose": "i2v"`，并用 `bindings` 指明 `image_loader`（首帧）与 `end_image_loader`（尾帧）。

## 局部重绘（inpaint）

「只改这块，别动别的」——在**插件配置页的「局部重绘」标签**里涂一下就行，聊天里不折腾遮罩：

1. 上传一张图（会自动按 `i2i.max_side` 等比缩小，画布尺寸对齐 8 的倍数）；
2. 用画笔涂出要重画的地方（画布上显示成半透明红色），涂错了按「画笔 / 橡皮」切换成橡皮擦；
3. 写一句想改成什么（可留空），调「重绘幅度」与「遮罩外扩」，点「开始局部重绘」；
4. 结果直接显示在下方，同时写进统计与画廊。

| 细节 | 说明 |
|---|---|
| 用什么节点 | ComfyUI **自带**的 `LoadImageMask`（读遮罩）+ `GrowMask`（遮罩外扩）+ `SetLatentNoiseMask`（只重画遮罩内），不需要额外模型或自定义节点 |
| 遮罩怎么传 | 页面把原图与遮罩都渲染成**同尺寸 PNG**，随请求一起发给插件；插件只做尺寸一致性校验，不做图像处理（不依赖 Pillow） |
| 遮罩语义 | 白 = 重画，黑 = 保留；所以 `LoadImageMask` 走 `red` 通道 |
| 遮罩外扩 | 默认 6 像素：把重画范围稍微扩出涂抹边界，接缝更自然（`GrowMask` 的 `expand`） |
| 重绘幅度 | 默认 1.0：靠遮罩保住其余像素，而不是靠低重绘幅度「糊」过去；想更保守可以调到 0.6~0.8（v0.15.1 修过一个 bug：这个默认值曾被 `i2i.denoise` 顶成 0.6，导致涂抹区域几乎不变） |
| 尺寸要求 | 原图与遮罩必须同尺寸（页面保证）；原图超过 2048×2048 会被拒绝并提示 |
| 会不会动到别处 | 不会。遮罩外的潜空间被原样保留，采样只发生在遮罩内 |
| 和聊天记录的关系 | 涂抹与遮罩只在浏览器里生成、随请求提交，不写进聊天；结果图会进统计与画廊（发起人记为「配置页」） |

> 权限提示：这个标签在插件配置页里，能打开配置页的人才能用（与改配置同权限）。

## 排错

| 现象 | 处理 |
|------|------|
| 「没有发现任何模型」 | 确认配置页里的 ComfyUI 地址正确，且 `models/` 下有模型；点「刷新模型」 |
| 「提交失败：缺少自定义节点：XXX」 | ComfyUI 端确实缺该节点，或工作流里残留了孤儿节点（插件已会自动剔除可达性之外的节点） |
| 报错里 `node_errors` 与 `details` 都是空的 | 插件已把实际提交的工作流存成 `last_failed_prompt.json`，把这个文件与 `/状态` 的输出发出来即可定位 |
| 出图分辨率 / CFG 明显不合适 | 架构识别不准。在配置页填「强制指定架构」`sd15` / `sdxl` / `pony` / `flux` / `sd3`；出图消息里会显示识别结果 |
| 手部崩坏、多手指 | 先确认架构正确（**SD1.5 被当成 SDXL 跑 1024 档是最大成因**），再开 Hires Fix（`--hires 1.5`），并在描述里写清手部动作（「双手抱胸」比事后加负面词有效） |
| 出图偏色、发灰、发绿 | 多为底模自带 VAE 有问题。把 `vae-ft-mse-840000-ema-pruned.safetensors` 放进 `models/vae`，再在配置页「强制使用指定 VAE」填该文件名 |
| 颜色/构图每次都不一样 | 正常现象。`--seed 12345` 即可复现；出图消息与画廊里都会显示本次种子 |
| 提示词太长没效果 | CLIP 每段只编码 77 token。ComfyUI 对超长提示词**不是截断**而是分段编码后拼接，所以长负面词依然生效、只是每个词的影响力被稀释；把最关键的词放前面 |
| `/反推` 的结果和图对不上 | 几乎都是**所用模型不支持看图**：AstrBot 会把图片换成字面量 `[Image]`，模型就开始编。发 `/状态` 看「看图」那一行；不支持时在配置页「反推专用模型」里选一个支持看图的提供商或填自定义接口，也可临时用 `/反推 --provider <id>` |
| 想看某张图的提示词和参数 | 配置页「统计」页的画廊里**点击图片**，弹窗可看可复制 |
| 「出图超时」 | 提高「出图等待上限」；前方排队任务多时，插件已按队列长度自动补偿等待时间 |
| 「排队等待超过 N 秒」 | 这是**插件侧**排队超时（还没轮到提交），不是 ComfyUI 慢。同时间出图的人多时，提高「同时出图上限」（多卡/开了并行）或「排队等待上限」，也可以先 `/状态` 看「并发」那一行的排队人数 |
| 模板「加载失败」里出现「界面格式…自动转换失败」 | 转换会在报错里说清是哪个节点、什么问题（控件数量对不上最常见）。可以按提示改用开发者模式的 Export (API)，或把该节点换成核心节点后重导 |
| 多后端里某台老是没被选中 | 看 `/状态` 的「后端」几行：`⛔ 熔断中` 说明它刚失败过（原因在配置页状态栏的明细里），等熔断结束或点保存配置重试；`❔ 未探测` 说明还没被派过任务 |
| 出图/出片过程中 ComfyUI 被关掉或机器重启 | v0.15.6 起会**快速报错**（连不上 60 秒 / 任务消失 6 轮即放弃），不再白等到 timeout。真机上遇到过整机重启（Kernel-Power 41），建议先解决供电/散热 |
| 视频在聊天里显示 0 秒 / 播不出来 | v0.15.5 起默认输出 **mp4（h264）**，就是为了这个。若你自带的模板还写着 `SaveWEBM`，换成 `CreateVideo` + `SaveVideo` 即可 |
| 视频「像静止图 / 没有动」 | 先看帧数与帧率：Wan 按 24fps、81~121 帧训练，帧数太少或播放帧率太低都会变成慢放/静止。v0.15.4 起默认已是 24fps / 81 帧；行内别写 `--fps 8`、`--seconds 1` 之类 |
| `/视频` 报 `unet_name 取值 xxx 不存在` 或 `not in list` | 说明选的权重要么不在 ComfyUI 注册的目录里，要么装载方式不对。先用 `http://<地址>/experiment/models` 看清目录映射，再确认 `/object_info/UnetLoaderGGUF`（GGUF）或 `/object_info/UNETLoader`（safetensors）的候选列表里有你的文件名 |
| 切了语言但文案没变 | 聊天文案保存配置后立即生效；插件页需要**刷新页面**（导航与标签页标题在加载时套用）。`auto` 跟随 AstrBot 界面语言，拿不到时用中文，可以在配置里显式指定 `zh-CN` / `en-US` |
| 文案里出现了类似 `queue.waiting` 的字样 | 说明这条键在当前语言文件里缺失（插件不会崩，只是显示键名）。补 `.astrbot-plugin/i18n/*.json` 即可，测试会拦住「两种语言键不一致」 |
| 插件页显示的还是中文 | 看 `/状态` 的「并发：进行中 / 排队」：排队数持续很高说明有人把名额占满了。单卡保持「同时出图上限 1」；想让一个人不能连开多张，把「单人同时出图上限」设为 1 |
| 一直在出图但没有进度提示 | 只有 ComfyUI 的 WebSocket 通了才有进度。老版本、或反向代理没转发 `/ws` 时插件会安静退回轮询（日志 debug 级），出图不受影响；本地 `http://127.0.0.1:8188` 直连一般都能用 |
| 进度提示太频繁 | 把「进度提示最小间隔（秒）」调大（默认 5），或直接关掉「出图过程中发送实时进度」 |
| `/扩图` 报「需要以下节点…没有安装」 | `ImagePadForOutpaint` / `SetLatentNoiseMask` 是 ComfyUI 自带节点，你的版本太老或缺了对应模块，升级 ComfyUI 即可 |
| 扩图接缝看得出来 | 调大 `--feather`（羽化带）；原图与生成区差异过大时，也可以把扩展量调小一点分几次扩 |
| `/图生视频` 报缺节点或模型 | 需要 Wan **I2V** 权重（T2V 的权重跑不了图生视频）；缺什么会列出来。用别的模型就自己建模板（`purpose: i2v`） |
| `/视频` 报缺节点或模型 | 视频走 ComfyUI 原生节点与视频模型，缺什么会列出来：按提示把 Wan 权重放进 `diffusion_models`、`umt5_xxl` 放进 `text_encoders`、`wan_2.1_vae` 放进 `vae`；或用你自己的视频工作流建模板（`purpose: t2v`） |
| 视频时长/大小和预期不一样 | 帧数会按 `4n+1` 对齐（时长可能比 `--seconds` 多一点点），超过「时长上限」会被截断并在日志里说明 |
| 局部重绘报「需要以下节点…没有安装」 | `LoadImageMask` / `GrowMask` / `SetLatentNoiseMask` 都是 ComfyUI 自带节点，报这个说明你的版本太老，升级 ComfyUI 即可 |
| 局部重绘报「原图与遮罩的尺寸必须一致」 | 正常不会出现（页面导出的两张图同尺寸）。若你用接口直连调用，请自行保证两张图同宽高 |
| 局部重绘接缝明显 | 把「遮罩外扩」调大（默认 6，可到 32~64），让重画范围盖住边界；或把重绘幅度降到 0.8 左右 |
| Flux 出图忽略了负面提示词 | 这是 Flux 的正常行为（CFG=1.0），请改用正向提示词或 `guidance` |

启动时插件会打印一条横幅，用来确认「跑的到底是哪一版」：

**v0.15.7** — 修 v0.15.6 的**误报**：正在跑的任务被判成「丢了」

- **问题**：任务在执行时 `/history/{id}` 里**本来就还没有它**（只有跑完才进历史）。
  v0.15.6 把这个正常状态当成「任务消失」，实测把一条正在采样的 30 步视频任务
  在 **22 秒**就判定放弃 —— 而它其实又跑了 4 分 23 秒并成功出片。
- **修复**：只有「**队列里没有** 且 **历史里也没有**」才计入消失计数；还在队列里
  （排队中/执行中）一律算正常等待。新增回归测试：mock 队列里挂着该任务时，
  即便历史为空、阈值调到最激进，也必须继续等待。
- 顺手补上中文提示词的实测结论（见下方「中文提示词能不能用」）。
- 测试：Python 526 / 前端 39 / API 面 55 全绿。

**v0.15.6** — 服务中途消失快速失败 + 图生视频「动起来」的实测配方

- **快速失败**：真机那次整机重启后，ComfyUI 连不上，旧实现会一直轮询到 `timeout`
  （我实测白等了 **30 分钟**才报「出图超时」）。现在：
  ① 连续 60 秒连不上 → 直接报「连不上 ComfyUI 了（可能被关闭或重启过）」；
  ② 服务通但任务从队列/历史里消失（连续 6 轮且 ≥20 秒）→ 报「任务已不在队列/历史里，
  请重新发一次」。正常任务完全不受影响。
- **图生视频要「动」，关键在提示词写动作 + 步数**。同一张首帧、同样 81 帧 @24fps 实测
  （相邻帧平均像素差，满值 255）：

  | 提示词 / 步数 | 运动量 | 产物 |
  |---|---|---|
  | 「她慢慢转头」（静态描述）+ 20 步 | 2.5 | 461 KB mp4 |
  | 「她转头看向镜头、长发随风飘动、镜头缓缓推近」+ 30 步 | **7.9** | 763 KB mp4 |

  也就是：**别只描述画面，要把「怎么动、镜头怎么动」写进去**；步数从 20 提到 30 也明显更活。
- 测试：+3 项断言（连不上快速报错、任务消失快速报错、正常任务不受影响），
  Python 525 / 前端 39 / API 面 55 全绿。

**v0.15.5** — 视频改成输出 **mp4（h264）**，修「聊天里显示 0 秒」

> 你反馈的「图生视频 0 秒」，除了帧数/帧率，还有一个更直接的原因：原来的模板用
> `SaveWEBM` 输出 **WebM/VP9**，而很多聊天端和播放器不认这个容器 —— 时长会显示成 0:00、
> 甚至直接播不出来。ComfyUI 官方模板用的是 `CreateVideo` + `SaveVideo`（默认 mp4/h264）。

- 四个视频模板（`wan_t2v` / `wan_i2v` / `wan22_t2v_gguf` / `wan22_i2v_gguf`）的保存节点
  统一换成 **`CreateVideo` + `SaveVideo`**，输出 **mp4（h264）**；帧率参数现在写在
  `CreateVideo` 上，模板的 `save` 绑定指向 `SaveVideo`。
- 真机确认这台机器的 `SaveVideo` 可用（`LoadImage → CreateVideo → SaveVideo` 秒级验证，
  产物 `h264 / mp4`）。
- 想回到 webm：模板是数据，把保存节点换回 `SaveWEBM` 即可（README 的模板章节有说明）。
- 测试：节点集合/输出锚点/fps 归属等断言同步更新（Python 522 / 前端 39 全绿）。

**v0.15.4** — 视频默认节奏改成模型原生（24fps / 81 帧），修「出片像静止图」

> 你反馈的「图生视频 0 秒、文生视频内容不对」，我用逐帧分析定位到了：
> 那次测试我为了快，用了 **17 帧 + 8fps 播放**。而 Wan 2.2 是按 **24fps、121 帧（5 秒）**
> 训练的（官方模板：`Wan22ImageToVideoLatent` 1280x704 **121 帧**、
> `KSampler` 20 步 / CFG 5 / uni_pc / simple、`ModelSamplingSD3` shift 8、
> `CreateVideo` **24fps**）。帧数太少 → 模型没有时间维上下文；播放帧率只有原生 1/3 →
> 看起来就是「一动不动」。逐帧统计也印证了：17 帧之间平均像素差只有 8.5（t2v）/ 2.7（i2v）。

- **Wan 系列自动跟随原生节奏**：没写 `--fps` 时用 **24fps**；什么都没写时用 **81 帧**
  （≈3.4 秒；官方最长 121 帧）。只写了 `--seconds` 就按 24fps 换算帧数；
  显式写了 `--fps`/`--length` 就完全尊重（想慢放/求快都行）。
- 其它视频模型（HunyuanVideo 等）不受影响，仍按配置里的 `default_seconds` / `default_fps`。
- 配置项提示也改了，写明「8~16fps 会让 Wan 出片像静止图」这件事。

- **排队时长与出图时长分开报**：出图消息里多一行 `⏳ 排队等待 Ns`，`/状态` 多一行

- 顺带把三处重复的队列提示闭包收成一个 `_queue_notifiers()`。
- **测试**：新增 24 项断言（并发上限生效、先来后到、位次、单人上限不堵队、排队超时、

**v0.6.1** — 反推：模型看不见图时明确报错，而不是编内容

  （`✅ 支持` / `❌ 不支持` / `❔ 未知`）；反推结果里标注**实际使用的看图模型**。

  新用户装完无法自举，`/刷新模型` 永远不可用。现在改用 AstrBot 自带的 `event.is_admin()`。
- **默认 LLM 回退必然抛异常**：`llm_generate` 的 `chat_provider_id` 是必填参数，旧版写了个不传它的
  回退分支。现在显式解析 provider，并在没有 LLM 时**退化为原描述出图**。
- **子目录模型被误杀**：旧版把含 `/` `\` 的模型名判为「无效」，而 ComfyUI 对子目录模型返回的正是
  `SDXL/xxx.safetensors`。现在按真实清单做白名单校验。
- **出图等待是无上限死循环**：旧版 `while True` 没有总超时。现在有硬超时、按队列长度补偿，
  并正确识别中断与执行失败。

新增：

- **工作流模板引擎**：模板成为可替换的数据文件，支持用户自带 API 工作流（图结构自动推导注入点）
- **架构自适应**：SD1.5 / SDXL / Pony / Flux 自动匹配分辨率、CFG、采样器、guidance
- **Flux 支持**：分离权重（`flux_unet`）与一体化底模（`flux_checkpoint`）两种模板
- **模型发现重写**：改用 `GET /models` + `GET /models/{folder}`，老版本回退到 `/object_info`
- **结构化错误**：解析 `node_errors` 翻译成中文，并给出「可用项」
- **按节点标题注入 + `bindings` 显式覆盖**、**节点能力探测**（缺节点直接报出缺哪个）
- **无指令出图**（可开关，默认关闭）、**配额落盘**、**图片保留策略**
- **修正版本声明**：原来写的 `>=4.9.2` 是错的（`astrbot.api.web` 依赖 FastAPI，自 v4.26.0 才有）
- **自带测试与 API 面核验器** `tests/check_api_surface.py`

移除：空转的「把几百个模型名分批喂给 LLM 生成风格标签」链路、从未被读取的死模板文件、
Pages 后端那套「猜 `file_response` 不存在」的三层降级、`/管理员` `/白名单` `/黑名单` 指令
（改由配置项承载且真正持久化）。

## 开发与测试

```bash
# 逻辑测试：自带 AstrBot / aiohttp 最小桩，不依赖第三方库
python tests/test_logic.py

# 插件页前端测试：用最小 DOM 桩真正执行 app.js（需要 Node）
node tests/test_pages_js.js

# API 面核验：对照真实 AstrBot 源码，确认插件用到的每个符号与方法都存在
python tests/check_api_surface.py /path/to/AstrBot
```

测试覆盖参数解析、尺寸对齐、模型名校验、错误解码、模型发现的两条路径、模板推导与注入、
按标题注入与 `bindings` 覆盖、非法绑定拒绝、不可达节点剔除、节点能力探测与缺节点报错、
存储与配额、Pages 的合并保存语义、出图并发闸门（上限、先来后到、位次、超时、名额不泄漏）、
WebSocket 进度解析与回退、`/取消`（排队中 / 队列中 / 执行中三种情况）、
扩图（扩展量默认值与限额、模板 `params` 注入与校验、不会退回文生图模板）、
局部重绘（模板角色绑定、遮罩/尺寸校验、临时文件清理、Pages 路由）、
多后端调度（清单解析、按负载选路、轮询/主后端策略、熔断与恢复、真的派给空闲那台）、
界面格式自动转换（控件对齐、`control_after_generate` 不错位、Reroute/静音/原语节点、

GGUF 量化（目录发现、按扩展名识别、装载方式隔离、Wan 2.2 TI2V-5B 模板与端到端）、
以及 mock ComfyUI 下的完整出图流程。

版本留档目录（`astrbot_plugin_comfyui_smart_vX.Y.Z`）里也带着同一套测试：
`tests/test_logic.py` 的 `_make_importable()` 会**按当前目录**构造包对象再导入，
所以「在哪个目录里跑测试，测的就是哪个目录的代码」（父目录里同时存在主仓库与留档目录时，
普通 `sys.path` 写法会命中主仓库，测出假结果 —— 这个坑已经踩过并修掉）。

`test_pages_js.js` 是前端唯一能抓到「变量改名漏改」「渲染时抛错」的测试 ——
`node --check` 只验证语法，不检查标识符引用是否有效。它用最小 DOM + 画布桩真正执行 `app.js`，
包括局部重绘的涂抹、橡皮、清空遮罩与提交 payload。

`check_api_surface.py` 不启动 AstrBot，而是直接读源码 AST，核验 import 的符号与调用的成员
（`Context` / `StarTools` / `AstrBotConfig` / `AstrMessageEvent` / `Image` / `astrbot.api.logger` /
Pages 请求代理与响应 helper）是否仍然存在，用于 AstrBot 升级后复检，
避免「某个方法改名后插件静默失效」。已在 **v4.26.0**、**v4.27.3**、**v4.28.1** 上跑通。
