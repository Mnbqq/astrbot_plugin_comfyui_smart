# 机器档位与模型推荐

配套配置项：`video.machine`（auto / low / mid / high）。

## 一、三档是怎么判定的

| 档位 | 显存 | 内存 | 视频上限（分辨率 / 帧数 / 步数） |
|---|---|---|---|
| **低配 low** | ≤ 10 GB | ≤ 16 GB | 832x480 · **97 帧**（≈4 秒 @24fps） · **12 步** |
| **标配 mid** | 12 ~ 20 GB | 32 GB | 1280x720 · **121 帧**（5 秒） · **30 步** |
| **高配 high** | ≥ 24 GB | ≥ 64 GB | 1280x720 · **161 帧**（≈6.7 秒） · **50 步** |

判定规则（`resolve_machine_tier()`）：

1. 配置里显式写了 low / mid / high → 直接用（想突破上限也随你）；
2. `auto`：按 **显存** 判定（≤10 → low，<22 → mid，否则 high）；
3. **内存不足 20 GB 时再降一档**（16G 显存 + 16G 内存 → low）：真机上「模型加载到一半报 `os error 1455`」基本都发生在内存这一侧；
4. 探测不到显存/内存 → 按 **low** 保守处理。

档位作用（含默认挑选偏好）：

0. **视频默认模型**：低配 / 标配档下没指定模型时，优先挑文件名带 `turbo` / `lightning` / `distill` / `schnell` 的加速版权重（8G 机器实测 74 秒 vs 281 秒）；高配档不干预（按清单顺序）。`video.t2v_model` / `i2v_model` 与 `--model` 优先级更高。
视频的**帧数上限**（`apply_native_video_defaults`）、**步数上限**、**尺寸预算**（图生视频按输入图缩放；图片用途给 2 倍预算）。想临时突破：聊天里 `--size` / `--length` 仍受档位约束，除非把档位改成更高一档。

## 二、低配（8G 显存 / 16G 内存）—— 实测可用清单

| 功能 | 模型 | 体积 | 放哪 | 实测 |
|---|---|---|---|---|
| 视频（质量） | `Wan2.2-TI2V-5B-Q4_K_M.gguf` | 3.2 GB | `diffusion_models/` | 20 步 / 81 帧 832x480 = **281 秒** |
| **视频（快，推荐）** | `Wan2_2-TI2V-5B-Turbo-Q4_K_M.gguf` | 3.2 GB | `diffusion_models/` | **4 步 = 74 秒**（快 3.8 倍，运动量反而更大） |
| 视频（最省） | `ltxv-2b-0.9.8-distilled-q8_0.gguf` + `ltx-video-vae.safetensors` | 2.0 + 0.8 GB | `diffusion_models/`、`vae/` | 8 步 / 97 帧 768x512 = **34 秒**（⚠️ 当前画质异常，待修） |
| 视频（更轻的 Wan） | `wan2.1_t2v_1.3B_fp16.safetensors` | 2.6 GB | `diffusion_models/` | 复用现有 Wan 模板与 umt5/wan VAE |
| 文本编码器（Wan） | `umt5-xxl-encoder-Q4_K_M.gguf` | 3.4 GB | `text_encoders/` | Wan 视频必需 |
| 文本编码器（Flux/LTXV 共用） | `t5-v1_1-xxl-encoder-Q4_K_M.gguf` | 2.7 GB | `text_encoders/` | Flux 与 LTXV 都用它 |
| VAE（Wan） | `Wan2.2_VAE.safetensors` | 1.3 GB | `vae/` | Wan 2.2 专用（2.1 用 `wan_2.1_vae`） |
| VAE（Flux/LTXV） | `ae.safetensors` | 0.3 GB | `vae/` | Flux 与 Lumina 用 |
| 图片（动漫，画质好） | `animagine-xl-4.0.safetensors` | 6.5 GB | `checkpoints/` | 1024x1024 / 28 步 = **31 秒** |
| 图片（写实） | `RealVisXL_V5.0_fp16.safetensors` | 6.5 GB | `checkpoints/` | SDXL 写实 |
| 图片（快，小） | `lumina_2.safetensors` | 9.9 GB | `checkpoints/` | 1024 / 30 步 = **59 秒** |
| 图片（提示词理解最好） | `flux1-schnell-Q4_K_S.gguf` + `clip_l.safetensors` | 6.3 + 0.23 GB | `diffusion_models/`、`text_encoders/` | 1024 / **4 步 = 35 秒** |
| VAE 修正（可选） | `sdxl_vae.safetensors`、`vae-ft-mse-840000-ema-pruned.safetensors` | 各 0.3 GB | `vae/` | 出图发灰时用 `--vae` |

> 低配档日常建议：出图用 SD1.5 或 Animagine XL（31 秒），视频用 **Wan 2.2 Turbo 4 步**（74 秒），
> 想更短就把 `--length` 压到 49（2 秒），耗时约减半。

## 三、标配（12~20G 显存 / 32G 内存）

| 功能 | 模型 | 体积 | 说明 |
|---|---|---|---|
| 视频 | `wan2.2_ti2v_5B_fp16.safetensors` | 9.3 GB | 单模型跑 720p；不再需要量化 |
| 视频（省显存仍可用） | 低配那套 GGUF | — | 同理适用，速度快很多 |
| 文本编码器 | `umt5_xxl_fp8_e4m3fn_scaled.safetensors` | 6.3 GB | 替换 GGUF 版，精度更高 |
| 图片 | Animagine XL 4.0 / RealVisXL V5 | 6.5 GB | 1024 出图更快，可开 Hires Fix |
| 图片（Flux 完整） | `flux1-dev-fp8`（11.9 GB）+ t5 fp8（4.9 GB） | 16.8 GB | 需要 32G 内存才舒服 |
| 14B 视频（可选） | `wan2.2_t2v_high/low_noise_14B_fp8_scaled`（各 13.3 GB） | 26.6 GB | ⚠️ 双模型两段式，插件暂未内置模板 |

## 四、高配（≥24G 显存 / ≥64G 内存）

- 视频：14B fp16（`wan2.2_t2v_*_14B_fp16` 26.6 GB / `i2v` 同规格）→ 720p 长片段，质量天花板；
  同样需要**双模型两段式**模板（高噪声 + 低噪声各跑一段），需要的话我可以加；
- 图片：Flux dev fp16（23 GB）、Qwen-Image（中文原生，unet 12~20 GB + 文本编码器 4.5 GB）
  —— **注意：插件目前只支持它的提示词写法（`prompt_style: natural`，见 README「自然语言编码器」一节），
  没有内置 Qwen-Image 工作流模板**，要自己在 `workflows/` 放一个 API 格式模板才能出图；
- 可以开 Hires Fix、更大 batch、更长视频（161 帧以上）。

## 五、不要下（在这些档位上都跑不动或看不到收益）

| 模型 | 原因 |
|---|---|
| Qwen-Image | 低配/标配内存不够（unet 12 GB + 编码器 4.5 GB） |
| Wan 2.2 14B fp8（26.6 GB） | 需要两段式模板 + 大显存 |
| 任何 fp16 的 Flux dev（23 GB） | 8~16G 显存放不下 |
| ControlNet / 放大模型 | 插件模板里目前没有对应节点；需要的话我再加模板 |
| 老式 `.ckpt`（pickle） | 加载慢且不安全，同架构 fp16 只要一半体积 |

## 六、GGUF 放哪个目录？（真机踩过的坑）

不同安装的 ComfyUI-GGUF 会把 `unet_gguf` / `clip_gguf` 映射到不同目录：

- 打开 `http://<你的ComfyUI>/experiment/models` 就能看到每个目录名的**真实路径**；
- 实测有一台机器：`unet_gguf` → `models/unet` + `models/diffusion_models`，`clip_gguf` → `models/text_encoders` + `models/clip`
  —— 也就是说 GGUF 权重该放 **`diffusion_models` / `text_encoders`**，而不是那个同名的空目录；
- 插件从 v0.15.3 起**只看 `.gguf` 扩展名**挑模板，所以放哪个被注册的目录都能认出来；
- 放好后发 `/刷新模型`，或直接查 `/object_info/UnetLoaderGGUF` 的候选列表确认。
